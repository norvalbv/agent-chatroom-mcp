# Proposed decision: rq1-claude-sonnet-harness-seed-is-pairing-key-not-randomization-control

From swarm-120129-s12h (concluded); report: swarms/swarm-120129-s12h/report.md. A human promotes this into docs/decisions/ with `guard-decisions add`; nothing is adopted automatically.

DECISION RECORD:
- **slug:** rq1-claude-sonnet-harness-seed-is-pairing-key-not-randomization-control
- **context:** The room built the RQ1 (paper/protocol.md §1) harness to run arm A vs arm C on real Claude Sonnet seats. During conclusion review, two pre-registration gaps surfaced that would have shipped silently if not caught: protocol §3 never states arm C's seat count (a number the mechanic literally depends on), and protocol §5's definition of "seed" (fixes task order, sampling temperature, and arm-C seat-role assignment) does not match what the harness's `--seed` flag actually does (a file-naming/pairing key only — the claude CLI exposes no temperature/seed flag, and arm C's seat-role order is always fixed regardless of seed).
- **ruling:** Seat count fixed at 3 for both scorable tasks (documented reasoning: minimum seat count at which `require_challenge`'s 2+-voter gate binds while leaving a reviewer distinct from proposer/challenger). `--seed` is documented as a pairing/dedup key only, not a randomization control, until the claude CLI exposes a sampling-seed flag or the harness adds its own seat-role randomization keyed on seed — both written into `paper/amendments.md`, dated, before any grid run, per the room's own pre-registration discipline.
- **consequences:** Protects the paper's grid results from a silent mismatch between what "seed" was pre-registered to mean and what it actually controls — a future reader of `paper/protocol.md` §5 alone would otherwise wrongly assume same-seed-across-arms controls real randomness beyond model non-determinism.
- **tradeoff:** RQ1's upcoming grid runs at n≥5 seeds will differ only through the model's own non-determinism, not through any harness-controlled variation in task order or seat-role assignment — accepted knowingly rather than delaying the harness to build seed-keyed randomization the CLI doesn't natively support.
- **researched:** No new external sources this run — evidence was entirely internal (protocol.md, bench-rq1.ts, `claude --help`, and the real pilot's result.json files). All sources already on the SETTLED AXES list.
- **rejected:** (1) Silently treating `--seed` as if it matched protocol §5's definition — rejected because it would misrepresent what varies between seeds in the eventual paper. (2) Leaving arm C's seat count unstated/re-derived per run — rejected because §2.2 requires it fixed per task tier, not tuned per run; an undocumented number would make the mechanic ablations (§2.3) incomparable across reruns.
- **revisit-when:** The `claude` CLI adds a sampling-seed or temperature flag, or the harness adds its own seat-role randomization keyed on seed — either would let `--seed` actually fix a random element as §5 originally intended, and this amendment should be revised or removed at that point.
