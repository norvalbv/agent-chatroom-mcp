DECISION RECORD
- slug: address-debt-is-a-set-not-a-slot
- context: ebbe80a added answerBeforeWaiting (refuse one wait after an unanswered @) and the silence auto-reveal so a quiet OpenRouter seat cannot hold a room. Verified this run: the gate keys on one id per participant, so a single pass or refusal disarms it for the rest of the run (hub.ts:931 vs 1004-1006), a discharged mention is re-advertised forever, a vote does not count as an answer, and the reveal only fires on 3 min with no post of any kind (hub.ts:820), never in a talking room and never with zero openings. Cost: the "quiet seat holds the room" failure the commit targeted returns after one nudge, plus false refusals; a seat that exits without leave_room stays a voter for 10 min because the SDK client never sends DELETE.
- ruling: (1) The hub records the set of address seqs a participant has answered (by chat, vote, challenge, amend or pass) and addressedBy excludes them; the wait gate keys on the newest unanswered address, once per address. (2) The reveal deadline is armed once per room when openings are first expected and re-armed only when openings.size or the joined set changes, not on chat; it fires with zero openings too, and the wait hint names the held state. (3) A seat calls leave_room for every joined room on every exit path and terminateSession() before close(). (4) A human is addressed by @name or reply_to only, never by substring; the refusal names the cause. (5) amend refuses a find that matches mid-word or shows the matched span with context in the notice.
- consequences: a weak seat is nudged once per address, never punished for answering by vote; rooms reveal on schedule while chatting; an exited seat releases its vote at once; agent-to-agent reports that mention the human are not capped; the conclusion document cannot be silently spliced.
- tradeoff: a set per participant instead of two ids; one more timer path in armNudge; @-only addressing means a human who writes "verifier, what do you think" without @ gets the generic responder path.
- researched: no arXiv sources read this run (none NEW versus the SETTLED AXES list). Local sources read: src/seat.ts, src/openrouter.ts, src/hub.ts, src/server.ts, src/index.ts, src/swarm.ts, src/spawner.ts, scripts/smoke.ts, scripts/openrouter-smoke.ts, logs/seat-trial-deepseek_deepseek-v4.1-flash.log, node_modules/@modelcontextprotocol/sdk client/streamableHttp.js, shared/protocol.js, server/webStandardStreamableHttp.js; two throwaway-hub reproductions.
- rejected: refusing every wait while addressed (deadlock loop); keying the gate on the oldest mention with pass writing the newest (the shipped design, wrong in both directions); treating an aborted SSE stream as a leave (evicts live POST-based seats that reconnect); reveal-on-first-nudge regardless of joins (exposes openings while a seat is still investigating); parallel_tool_calls=false to dodge the interleaving risk (loses the seat's read-and-wait batching for a provider-dependent 400).
- revisit-when: a trialled model still ignores a second @-address after the set-based gate ships; or a room with expected openings stays unrevealed past one nudge interval in any run; or a seat exit leaves an active participant longer than 60 s; or a human's @-less question goes unanswered in more than one run in five.
- RE-TARGET hub-carries-what-it-knows (2026-09-17 target entry): its ruling (3) "an agent shown an @-addressed message ... is refused once ... pass clears the debt" and its anchored bet "a once-only refusal plus the hint as a user turn is enough" are contradicted by the live reproduction above: the refusal fires at most once per participant per run, pass does not clear the debt from the hint, and a vote is not an answer. Its "Positive: a quiet seat cannot hold a room's openings" is also contradicted: the reveal never fires in a chatting room or with zero openings.
