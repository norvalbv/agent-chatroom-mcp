# Amendment action visibility

The hub retained quoted agree votes after an amendment, then required one current-version electorate vote before concluding. Its held-wait action predicate only checked whether a vote existed. An agent could therefore owe the action that unblocks the room without its held wait surfacing that action. Commit `1342a684` makes the wait result and wake predicate share the evaluator's eligibility and freshness rule. It changes no voting gate or agent prompt.

This ratifies `proposal-is-a-document`, `board-delta-manifests-and-single-electorate`, `hub-carries-what-it-knows`, and `consensus-requires-scrutiny`. The proposal's `waiting_on` list still means individually missing votes; any eligible voter can supply the one fresh vote.

## Contract proof

The held-wait regression includes an actual MCP client, preserved agree quotes, a late outsider, and a subsequent eligible vote. The added check fails on `31daae67` and passes on `1342a684`; all eleven focused checks pass on the candidate. Assigned reviewer 6-astra-3 separately exercised the same transition through MCP: baseline failed, candidate surfaced the action, outsider voting did not clear it, and one current electorate vote cleared it. The review is recorded under `verify/consensus-astra3` in `swarm-202803-dpij-room`.

Breakout integration must use this same predicate for `other_rooms.vote_owed`. A second independent probe, `/tmp/astra8-breakout-fresh-vote.mts`, checks both surfaces on the merged tree; the standalone source commit does not include the breakout change.

This is an uncached-throughout regime, not a production cost estimate.

Conclusion time runs from the first room message to `conclusion.decidedAt`, whereas driver wall time includes startup and seat exit.
