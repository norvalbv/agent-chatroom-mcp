Build the pool-throughput harness pre-registered in docs/experiments/2026-09-23-pool-throughput.md. Read it first: it is the spec, and the harness must implement it exactly. Extend the existing build-suite runner (scripts/bench-build-runner.ts, scripts/bench-build-runtime.ts: isolated workspaces, deadlines, stopping seats, usage and cost records) where it fits rather than duplicating it. Each item needs a failing regression test first, a fix, a commit on your branch, and a verify/* entry from a seat that did not build it.

1. Pool format and `validate`. A pool is pool.json {name, repo, base_commit, deadline_min, items: [{id, title, brief}], split: [[ids], [ids], [ids]]} plus a manifest sha256 lock. Its hidden side lives in a separate root (default ~/.agent-chatroom-hidden/<pool>/<item-id>/) with the item's test files, cmd (the shell command that runs them from the repo root) and reference.patch. `validate` checks every item in a fresh worktree at base_commit: the hidden test fails; with reference.patch applied, it passes. Report per item.
2. `run --pool P --arm solo|split|room3|room15 --rep N`. Fresh git worktrees of the pool's repo at base_commit under a scratch root outside the repo. Generate each setup's brief from the manifest: solo gets all items; split gives each of three seats its third; rooms get all items and "organise yourselves; integrate onto one branch before the deadline". Every brief states the deadline and asks for one commit per item with the item id in the message. Launch solo and split as claude -p seats (claude-opus-5-5, full access, auto-memory off, no settled axes) the way the build runner does; launch rooms with dist/swarm.js --flat --agents 4 or 15 --models claude-opus-5-5 --verifier-model claude-opus-5-5 --full-access --require-verification --no-carry --cwd <worktree> on a private hub port (CHATROOM_INSECURE_LOCAL=1). Stop every process at the deadline. Record per-seat usage and cost (for a seat stopped early, estimate from partial usage and mark it as an estimate) and the active account from the account switcher's log.
3. `finalize`. The setup's final head: solo, its branch; split, its three branches merged in fixed order, a conflict keeping the earlier branch and being recorded; rooms, the integration branch they declared, else their worker branches merged like split.
4. `score --run R`. In a clean worktree of the final head, copy in each item's hidden test files (never reference.patch), run its cmd, record pass or fail per item; run the project's existing test suite; write score.json.
5. Leakage audit. Scan every seat's transcript and tool calls in the run for the hidden root's path or any hidden test file name; a hit marks the run void.
6. A two-item dry-run pool and a fake-seat mode, so validate, run, finalize, score and the audit are all tested offline with no model calls, plus regression tests in the offline suite.

Never write the hidden root's path into any brief a builder sees, and never copy reference.patch anywhere a builder can read.
