# Room harness intuition and tool affordances

**No unprompted breakout formed in any of the nine scored trials.** Separate forced-split trials recorded better parent placement, with incomplete served-build provenance; this run did not demonstrate more spontaneous organization. The short workload and a faulty frozen factual answer key limit interpretation; the corrected factual scores and all costs are retained below.

This engineering follow-up asks whether the hub lets its existing frontier-model seats act on their judgment. It examines available actions, returned state, hidden prerequisites and action costs. It does not test weaker models or add system-prompt reminders. Tool adoption, task correctness, cost and completion time are separate outcomes.

## Measurement interpretation

The historical audit must separate attempted calls, successful calls, actual state changes and calls absent from room-scoped instrumentation. A roomless discovery call can be missing from a room log even when it occurred. A successful `request_agent` call is not proof that the recruit joined or contributed; a zero kick count is not proof that a kick was needed.

For paired behavior trials, keep the brief and task oracle fixed. Confirm cache state from each seat's first provider request rather than from a fresh session or a nonce in the user message. Report costs per model turn, turns, tool calls, oracle result and conclusion time, retaining missing usage fields and failed runs. A deterministic regression proves a contract change; a live trace proves that agents exercised it; only repeated controlled trials can support a broader behavioral improvement claim.

The cache protocol uses `DISABLE_PROMPT_CACHING=1` for the private Claude trials, as documented in [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching#disable-prompt-caching). This is an uncached-throughout condition, which differs from a cold first request followed by normal reuse. Trace inspection must establish the actual cache reads; the environment variable alone is not evidence of compliance.

At starting revision `31daae67`, `src/swarm.ts` writes a Claude MCP configuration containing only `chatroom`, and `src/claude-args.ts` always supplies `--strict-mcp-config`. The launcher allows WebSearch and WebFetch unless `--no-web` is set. Thus installed arXiv MCP tools are not available to these Claude seats through inherited configuration. This is an interface difference, not evidence that those seats cannot research through the available web or shell tools. The run does not change this external-tool configuration.

## Exit receipts: a narrower correctness fix

A killed-client probe with a controlled clock and a second real-time probe confirmed that a retained MCP session could block replacement after process death. The later exit-receipt change closes sessions bound to an authenticated launch key when the launcher reports that its child exited. Independent checks rejected the first implementation because normal completion could precede the receipt; the corrected `3150e4a9` waits for the bounded receipt before resolving the run. Exact-key isolation, duplicate receipts, conservative behavior without a receipt, HTTP replacement and launcher ordering were independently exercised before and after the change.

This is a conditional correctness fix, with no new repeated model-outcome or adoption claim. Delivery remains best effort: a network or unsuccessful HTTP response can lose the receipt, the launcher's forced-shutdown deadline can preempt it, and after a hub restart an unreconnected seat has no bound transport for the receipt to close. The restart grace period can therefore still delay replacement. A launcher killed with SIGKILL sends no receipt, nor do seats started outside the swarm launcher or spawner. It does not make every dead seat immediately replaceable.

A separate inherited draft-reveal defect surfaced during the landing gates: an early deadline callback could leave drafts readable by elapsed time without persisting or announcing the reveal. The isolated `f5101620` correction rearms the existing deadline when the reveal is not yet due. Independent deterministic probes fail before and pass after, including disk replay and single announcement. This preserves `settle-disputes-by-spec-not-count`; it supplies no additional model-outcome claim.

## Interpretation and reproducibility

The supported changes expose current policy facts, distinguish temporarily absent seats from departed ones, surface owed actions and preserve parent-room context when existing seats split. Existing seats could already join another room; the added relationship and carry-back are the relevant new affordances. The false launch notice discovered during liveness testing is separately corrected and independently exercised. No new system-prompt rule, mandatory split or staffing quota is introduced.

These observations support particular interface corrections and task-specific tradeoffs. They do not establish that seats now organize themselves spontaneously, that more recruiting or kicking is desirable, or that every historical non-use had a harness cause. The original capability and prompt-reminder alternatives were not experimentally compared. This room itself used public claims, quiet threads, recruitment and kick votes without a breakout on the unchanged running hub. Recovery followed owner intervention during a usage outage and crossing handoffs; it is an operational observation, not evidence of spontaneous organization or a before/after trial. One unresolved visibility gap also appeared: two recruits listed with no requested model were stopped over uncertainty about their identity, but independent native-trace inspection subsequently identified both as Opus 5.5. Requested model configuration and observed running model are different facts; the directory did not expose the latter.
