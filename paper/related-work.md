## 1. Multi-agent debate and deliberation

| Source | Title (fetched) | Claim taken | How this system differs |
|---|---|---|---|
| [arXiv:2305.14325](https://arxiv.org/abs/2305.14325) | Improving Factuality and Reasoning in Language Models through Multiagent Debate | Multiple LLM instances debating over rounds and converging on a consensus answer improves factual accuracy and reasoning over single-model sampling. | Establishes the base claim this project builds on (debate can help); **not novel here**. This system adds structural gates (blind openings, challenge requirement, quote-checked votes) around that same debate loop rather than proposing debate itself. Cited in `consensus-requires-scrutiny`, `README`. |
| [arXiv:2305.19118](https://arxiv.org/abs/2305.19118) | Encouraging Divergent Thinking in Large Language Models through Multi-Agent Debate | Plain multi-agent debate suffers "Degeneration-of-Thought" (agents converge and stop generating novel content); a judge role and enforced divergence counteract it. | This system's blind-opening reveal (`submit_opening`, revealed only once all have answered) is a structural anti-anchoring device aimed at the same failure mode, but the hub never grades or scores divergence itself — no judge role, no measured diversity metric. The comparison is asserted, not measured. |
| [arXiv:2311.17371](https://arxiv.org/abs/2311.17371) | Should we be going MAD? A Look at Multi-Agent Debate Strategies for LLMs | Multi-agent debate does not reliably beat simpler baselines (e.g. self-consistency / sampling-and-voting); benefit is protocol-dependent. | Directly motivates why `paper/protocol.md` requires a budget-matched single-agent control and a no-chat builder+reviewer pair as baselines, not just "chatroom vs nothing." This is the single strongest piece of literature against assuming the chatroom helps by default. |
| [arXiv:2509.23055](https://arxiv.org/abs/2509.23055) | Peacemaker or Troublemaker: How Sycophancy Shapes Multi-Agent Debate | Sycophancy (excessive agreeableness) collapses multi-agent debate into premature, incorrect consensus faster than single-agent error. | This is the specific failure mode the `require_challenge` gate (`consensus-requires-scrutiny`, `docs/decisions/consensus-requires-scrutiny.md`) and quote-checked `agree` votes are aimed at: a challenge must name the weakest claim before quorum can pass, and an `agree` vote must quote verbatim proposal text, both raising the cost of reflexive agreement. **The mitigation is structural, not learned**, and its effect on premature consensus specifically has not been measured against this paper — only the unrelated attention-gate A/B exists (one task, one seed, `measure-task-success-on-a-machine-oracle`). |
| [arXiv:2606.29270](https://arxiv.org/abs/2606.29270) | Minority Sentinel: When to Overturn Majority Voting in Multi-Agent LLM Debates | A learned meta-classifier can detect when a debate's minority position is correct despite losing the majority vote, and override it. | This system has no analogous override: supermajority quorum (`consensus-requires-scrutiny`) means a correct minority is simply outvoted, full stop. This is a real, named gap — the chatroom's challenge mechanic can *block* premature consensus but cannot *overturn* a wrong majority once quorum is reached. Worth stating in `paper/protocol.md` threats-to-validity. |
| [arXiv:2609.00683](https://arxiv.org/abs/2609.00683) | Creative Generation via Multi-Agent Debate: Does Debate Suppress Diversity? | Convergence-seeking multi-agent debate suppresses output diversity on open-ended tasks; process consensus is reached at the cost of the diversity the task actually needed. | Directly supports `measure-task-success-on-a-machine-oracle`'s premise that a process metric (consensus reached, reply rate) is not task success — this room's own oracle tasks are closed-answer, so diversity loss is out of scope for the primary benchmark, but it is a threat to validity if the task suite is ever extended to open-ended tasks. |
| [arXiv:2609.03619](https://arxiv.org/abs/2609.03619) | Remember and Reweight: Enhancing Multi-Agent Debate with Experience Memory and Confidence Estimation (R²-MAD) | Per-agent reliability can be estimated from confidence signals and used to reweight contributions, addressing "shared misconception" errors that plain majority voting cannot catch. | This system's nearest analogue is the assigned-reviewer + `verify/*` gate (`done-means-independently-verified`): a *structural* reliability check (a named other seat must produce a machine-checked JSON verdict) rather than a *learned* one (confidence-weighted reliability scores). The system does not claim the structural version is better — that comparison is untested. |

## 3. Verification, self-report reliability, and group-decision stability

`done-means-independently-verified` cites coalition-formation game theory (not LLM verification papers) for the electorate/quorum design; this section reports what those sources actually say and is honest that they are a different literature than "can an LLM's self-report be trusted."

| Source | Title (fetched) | Claim taken | How this system differs |
|---|---|---|---|
| [arXiv:2211.17169](https://arxiv.org/abs/2211.17169) | Causes of Stability in Dynamic Coalition Formation | Emotional dynamics (resentment on departure, appreciation on joining) can guarantee convergence to stable coalition outcomes under mild conditions where classical models do not converge. | This is game-theoretic coalition-formation literature, not LLM-agent literature; it is cited to justify that *some* group needs a stability argument for join/leave dynamics (`self-organising-teams-by-claims-and-recruitment`'s claim/recruit model), not that this system implements anything resembling the paper's mechanism. The link is thematic, not architectural — worth flagging plainly rather than overstating. |
| [arXiv:2312.09119](https://arxiv.org/abs/2312.09119) | Stability in Online Coalition Formation | Analyzes stability concepts (in additively separable hedonic games) when agents arrive sequentially and must be assigned immediately, rather than optimizing social welfare. | Same caveat as above: relevant to the *idea* that this system's rooms admit participants over time (`join_room` sequential arrival, `expected_participants` gating), not to any specific mechanism the hub implements. |
| [arXiv:cs/9810005](https://arxiv.org/abs/cs/9810005) | Anytime Coalition Structure Generation with Worst Case Guarantees | An anytime algorithm that bounds coalition-structure quality relative to optimal and tightens the bound with more computation. | Cited in `docs/swarm-protocol-spec.md` and `done-means-independently-verified` as background for group-formation guarantees; this system's supermajority quorum (`consensus-requires-scrutiny`) is a fixed heuristic (`ceil(0.75 x electorate)`), **not** a worst-case-guaranteed algorithm — no bound is computed or proven at runtime. Stating this precisely matters because the decision doc's citation could otherwise be read as claiming a formal guarantee that does not exist in the code. |

The self-report reliability half of this section's brief — "can an agent's own claim that it verified something be trusted" — is answered by this system's own mechanism (`done-means-independently-verified`: a `verify/*` entry only counts if it parses as JSON with `exit_code: 0` and the exact proposal id, from someone other than the proposer) rather than by an external LLM-reliability paper found in this run. No paper specifically on LLM self-report calibration was fetched in this session; that is a gap in this related-work pass, not a claim that none exists.

## 5. Evaluation methodology for agent benchmarks

| Source | Title (fetched) | Claim taken | How this system differs / how it is used |
|---|---|---|---|
| [arXiv:2306.05685](https://arxiv.org/abs/2306.05685) | Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena | Strong LLMs used as judges reach over 80% agreement with human preferences on chat-assistant comparisons via MT-Bench and Chatbot Arena. | The 80% figure is a ceiling, not a guarantee, and it is a *preference*-agreement number, not a *correctness* number. `measure-task-success-on-a-machine-oracle` cites this paper as part of the reasoning to reject LLM-as-judge as the primary scoring method for this project's benchmark, using hidden-fixture machine oracles (full-string equality after documented normalization) instead. This system does not dispute the 80%-agreement finding; it argues preference agreement is the wrong target for a system whose claim is about task correctness. |
| [arXiv:2608.30373](https://arxiv.org/abs/2608.30373) | Beyond Consensus: Downward Bias and Role Asymmetry in Multi-Agent LLM Judges for Subjective Evaluation | Assigning asymmetric roles (e.g. strict vs. lenient) to multi-agent LLM judges introduces a systematic downward bias that their own consensus process does not self-correct. | Reinforces why this project's benchmark harness never has an LLM judge a model's answer — even a multi-agent judging *panel* is shown here to carry a directional, uncorrected bias. The chatroom's own challenge/vote structure superficially resembles a "panel of judges," which makes this paper a direct warning against ever using the chatroom's own consensus mechanism as the scorer of a benchmark task about the chatroom. |
| [arXiv:2609.02942](https://arxiv.org/abs/2609.02942) | Judging LLM-as-a-Judge: Concerning Rubric Artifacts in LLM-based Automated Text Generation Evaluation | Rubric text itself encodes evaluative signal, letting scores be predicted from the rubric independent of the candidate response — a validity failure of rubric-based LLM grading. | Further grounds for the "oracle only, no model judging a model" rule (`measure-task-success-on-a-machine-oracle`): even giving a judge a rubric does not fix judge validity. This is why the two existing oracle tasks (bench-fact-check, bench-bug-fix) are scored by exact-match/hidden-test pass, not by a rubric-following judge model. |
| [arXiv:2404.06654](https://arxiv.org/abs/2404.06654) | RULER: What's the Real Context Size of Your Long-Context Language Models? | Synthetic long-context benchmarks with simple needle-retrieval overstate real capability; RULER adds diverse needle configurations and multi-hop tasks to resist this kind of gaming. | Analogous warning for this project's own task suite: a fixture that is answerable by a single shallow pattern-match (the equivalent of "one needle") overstates what an oracle task actually measures. `paper/protocol.md`'s task-suite section should apply RULER's diversity-of-configuration lesson to task *design*, even though RULER itself benchmarks context length, not agent correctness. |

## What prior work makes non-novel, stated plainly

- **Multi-agent debate for factuality/reasoning** (2305.14325) and **general multi-agent conversation frameworks** (2308.08155 AutoGen, 2303.17760 CAMEL) are established. This system does not claim to have invented multi-agent LLM collaboration.
- **Multi-agent debate's documented failure modes** — degeneration of thought (2305.19118), no reliable edge over simpler baselines (2311.17371), sycophancy-driven premature consensus (2509.23055), diversity suppression (2609.00683), majority-suppressing-a-correct-minority (2606.29270) — are all pre-existing findings. This system's mechanics (blind openings, challenge gate, quote-checked votes, supermajority quorum) are a specific, untested response to those known failure modes, not a discovery that the failure modes exist.
- **Rejecting LLM-as-judge as a primary scorer** (2306.05685, 2608.30373, 2609.02942) is directly supported by prior work; the project's `measure-task-success-on-a-machine-oracle` axis follows this literature rather than breaking new methodological ground.
- **Cost-aware serving via model cascades/routing** (2305.05176, 2606.27457) is established for the query-routing case; this system's cost approach (context trimming at the seat level, `token-cost-is-resent-context`) is a different lever aimed at coordination overhead specifically, not a new instance of cascade routing.

**The narrow, honest contribution claim:** what has not been found in this run's search is a prior evaluation of a *hub-enforced* combination of these specific mechanics together — blind-opening reveal, mandatory pre-quorum challenge, quote-verified agree votes, machine-parseable `verify/*` gate with hub-assigned (not self-selected) reviewer, and supermajority electorate counted per connection — applied to LLM agent coordination, nor a benchmark of that combination against a budget-matched single agent and a no-chat builder+reviewer pair on hidden-fixture machine-oracle tasks. That combination, and that comparison, is what `paper/protocol.md` pre-registers. It is a narrow claim about an untested combination of known parts, not a claim of a new debate mechanism or a new judging method.
