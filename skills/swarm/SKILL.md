# Swarm

One command runs the whole thing. Two shapes:

- **Planned** (default): a planner agent splits the task into sub-questions, worker agents investigate each in their own room, each room's lead carries its conclusion to a leads room, and a verifier with a unanimous-quorum vote checks the claims against the real project. Use when the sub-questions are obvious (bugs, fixes, a design with known parts).
- **Flat** (`--flat`): no planner. Every agent gets the raw question in ONE room on the minimal prompt and organises itself: claims areas on the board, recruits with `request_agent`, breaks out into sub-rooms and brings results back. The verifier sits in the same room. Use for brainstorms, open questions, "what should we do about X", anything where the shape of the work is itself unknown. Benji prefers this when the task is loose.

## Run it

Always run the orchestrator. Do NOT hand-roll the swarm by spawning subagents that call the chatroom tools yourself.

```bash
cd "$HOME/Desktop/Personal and learning/agent-chatroom-mcp"   # same folder under the home directory on both machines
node dist/swarm.js "<task in the user's words>" --agents <N> --cwd "<absolute project dir>" \
  [--flat] [--models sonnet,haiku,fable,opus] [--lead-model opus] [--verifier-model fable] \
  [--apply | --full-access] [--codex <k>] [--openrouter <k>] [--openrouter-reasoning low|medium|high] [--timeout <minutes>] [--done-when "<criterion>"] [--verify "<what the verifier checks>"]
```

- `--agents N`: total including the verifier (default 4). "a few" = 4, "lots" = 8. **Flat mode caps at 12** (one room holds 12 live agents; the launcher refuses more instead of deadlocking).
- `--models a,b,c`: Claude model mix rotated over workers. Aliases that work: `haiku`, `sonnet`, `opus`, `fable`. `--lead-model` (planned only), `--verifier-model`, `--planner-model`. A good mixed run: `--models sonnet,haiku,fable,sonnet,opus --lead-model opus --verifier-model fable`.
- `--codex k`: k workers on OpenAI Codex (`codex exec`), rotating over `--codex-models` (`gpt-6-astra,gpt-5.6-sol,gpt-5.6-terra`). **Only when the user asks and has quota**; a Codex seat that dies on quota still counts toward the room's expected participants. Codex hooks need trusting once (`/hooks` in Codex) before its gates run.
- `--openrouter k`: k workers on OpenRouter models, rotating over `--openrouter-models` (default `deepseek/deepseek-v4.1-flash,google/gemini-3.8-flash,z-ai/glm-5.3`; any slug from openrouter.ai/models works). Needs `OPENROUTER_API_KEY` exported — the launcher refuses to start without it rather than leaving dead seats in the quorum. Codex and OpenRouter seats share the non-lead seats, so `--codex k --openrouter m` needs `k + m <= agents - 1`. A seat is `src/seat.ts` (provider-independent loop: full hub tool descriptions and the hub's instructions in the system prompt, the hub's `hint` lifted into a user turn when it is about this seat, reasoning blocks passed back, a wall-clock budget equal to `--timeout` after which it leaves the room) plus `src/openrouter.ts` (the provider and CLI). Local tools: `read_file` / `list_dir` / `search` / `web_fetch` / `run_command`, read-only unless `--full-access` (then each seat gets its own worktree and branch with `node_modules` linked, so `npm run build` and the tests work there). Pattern kills (`pkill`, `killall`) are refused in every seat; a brief that has agents start test hubs must tell them to stop them by pid (`kill $(lsof -ti:PORT)`), and never say "kill your hub" without that, because a Claude verifier with Bash has no such guard. **Before trusting a new model in a swarm, trial it**: `OPENROUTER_API_KEY=… npm run seat:trial -- --model <slug>` runs one seat against a throwaway hub and prints whether it joins, opens, replies when @-addressed, engages with a proposal and leaves, with timings and cost (log in `logs/`).
- **Proactive handoff** (OpenRouter/`src/seat.ts` seats, `docs/decisions/r1-proactive-handoff.md`): a seat still holding a `claim/*` writes `handoff/<area>` and leaves cleanly before its step cap, a token budget, the context ceiling, or (`--handoff-idle-turns`, default 20) too many consecutive turns producing no actionable hub hint and no outbound `send_message`/`board_set` — instead of dying mid-work or trimming its own claim out of context. Flags: `--handoff-step-max`, `--handoff-step-fraction` (default 0.75), `--handoff-prompt-tokens` (default 6,000,000), `--handoff-context-fraction` (default 0.9), `--handoff-idle-turns`, `--no-handoff` to opt out. Verified offline, no network: `scripts/handoff-regression.ts`.
- `--apply`: the verifier may implement the agreed fix on a new git branch and prove it with tests. `--full-access`: workers edit files too, each on its own worktree/branch; the verifier merges.
- `--named`: real names inside worker rooms (default pseudonyms). Flat rooms name agents by model (`sonnet-1`, `fable-6`) so the dashboard shows the mix.
- `--timeout`: minutes before stragglers are killed (default 30; use 45 for 12+ agents or research-heavy briefs).
- `--require-verification`: the launcher creates the room with `require_verification` before any seat joins (via `POST /rooms/:room/create`), so no proposal can pass without a `verify/*` board entry by someone other than its author whose first line is JSON `{"proposal":"<id>","command":"<what you ran>","cwd":"<working dir>","exit_code":0,"output_tail":"<last lines of real output>"}` (commit optional; prose may follow) naming that proposal with `exit_code` 0 — an entry without that parseable head, or with a non-zero `exit_code`, does not count. Use it for build rooms: "done" is then hub-enforced, not a vote.
- **Reviewer assignment**: creating `claim/<area>` assigns a reviewer, not a volunteer — the hub picks the least-recently-verifying active participant who is not the owner and not a second identity on the owner's own MCP session (never-verified sorts first, ties break by earliest join), fixed at creation and unchanged by later edits to the same claim. Both the claimant and the reviewer are told; the reviewer's notice is a hub-authored `@name` chat line (not a system notice — chat-kind is what makes the wake survive the read cursor already having moved past it) that wakes a held `wait_for_messages(hold_until_actionable=true)`. While that reviewer is active, `require_verification` accepts only their `verify/*` entry naming the proposal; once they leave, it falls back to any non-author entry, so nobody is stuck waiting on someone who is gone. See the claim's `reviewer` field in `room_status`/`board_get` and the dashboard's People ("reviewing: …") and Board tabs.
- **Baseline-freeze guard** (`.husky/pre-commit`, `scripts/guard-baseline-freeze.mjs`): a commit touching `.devkit/baselines/**` or `.devkit/config.json` is refused unless a `verify/baseline-<area>` board entry by a different seat names the staged tree (`git write-tree`) — an author cannot bank their own baseline change unreviewed (e.g. commit 15d3717, which raised the fan-out cap in the same commit as the growth it grandfathered). Fails CLOSED if the hub is unreachable. The maintainer's override (`CHATROOM_BASELINE_FREEZE_OVERRIDE=1 git commit ...`) is excluded from every seat's environment (`SEAT_ENV_EXCLUSIONS`, `src/env.ts`) — do not try to set it from a seat.
- `--verifier-openrouter <slug>`: the verifier seat on an OpenRouter model (a run on a free model then costs nothing).
- **Self-improvement lobby** (`--flat --agents 40 --openrouter 39 --verifier-openrouter <slug> --prompt loop.md --quorum supermajority --require-verification --respawn --timeout 240`): `--quorum supermajority` (ceil(0.75 x electorate)) is now the recommended default for flat runs that used to pass plain `majority`; `unanimous` and `majority` are still available (`--quorum unanimous|majority|supermajority`). One large room on `prompts/loop.md` (quiet messages for working exchanges, fetched-not-remembered research, break-out rooms for depth and for building with worktrees per write-enabled recruit, hub-enforced verify entries). Needs the hub started with `CHATROOM_MAX_LIVE_PER_ROOM=80 CHATROOM_MAX_LIVE_AGENTS=400 CHATROOM_MAX_RECRUITS_PER_ROOM=400 CHATROOM_MAX_RECRUITS_PER_RUN=1000 CHATROOM_MAX_RECRUIT_DEPTH=4 CHATROOM_MAX_ROOMS_PER_RUN=100`. Seats absorb three empty waits per model turn (`--idle-waits`), which is what fits 40 seats under a 100 req/min model limit; `--respawn` relaunches a seat that exits while its room is open.
- A repeat `join_room` from the same session and name is idempotent, and the seat refuses to join a room it is already in (under any name) and reminds the model of its identity every turn; a duplicate persona like `bench-3b` beside `bench-3` was a context drop, not a second agent (`scripts/session-identity.test.ts`).
- A seat heads-down in local work shows as `working: <tool> · <age>` in the People tab (seat heartbeats over HTTP each step); `last_seen_at` in `GET /rooms/<room>` is the latest of hub call and heartbeat. Judge liveness by that, not by message count; click the person to see their last 60 steps with the actual commands (`GET /rooms/<room>/participants/<name>/activity`).
- `leave_room` needs a `reason` (what was finished, where it is on the board, what is undone); it is posted in the room and shown in the dashboard's People tab, so a departure can be read and, if others disagree, answered with a recruit. While the room is open, a leave that abandons a `claim/*` without a `handoff/*` or an unanswered @-ask is refused once with what to write first (`scripts/leave-regression.ts`). Once the room has concluded or closed, `leave_room` never refuses for either reason (a reason is still required): the hub announces every `claim/*` released in one system line, without deleting them (a seat's note is sometimes the only record of what it did), and board writes (`board_set`) are refused outright from then on, with a plain message — `verify/*`, `handoff/*` and `claim/*` entries all stay readable with `board_get` (`scripts/leave-post-conclusion-regression.ts`).
- `--respawn`: a seat that exits while its room is open is relaunched as `<name>-r1..r3` only when the room still needs it: non-zero exit, a `claim/*` of theirs with no `handoff/*`, the verifier, or fewer active seats than the floor, which is 3 between proposals and, while a proposal is open, max(3, ceil(expected/2)) for majority, max(3, ceil(expected*0.75)) for supermajority, or expected for unanimous. A seat that finished, handed over and left is not replaced; the launcher logs the reason either way (`src/respawn.ts`, `scripts/respawn-regression.ts`). Two runs of 20 with unconditional respawn churned 70 replacements in 30 minutes.
- **Fleet** (`node dist/fleet.js fleet/<spec>.json --model <slug> [--only a,b] [--consolidate --consolidate-from <summary.md,...>] [--require-verification] [--full-access]`): one flat run per area from a JSON spec (areas with `lenses` become competing rooms), staggered, with every conclusion gathered into `swarms/fleet-<id>/summary.md`; `--consolidate` runs one more room that merges the summaries into one ranked consensus. Rate limits are per model and account: `deepseek/deepseek-v4-flash-0731` allows 100 requests/min, which fits about 36 seats (three rooms); `fleet/run-batches.sh` runs the rest back to back.

Every prompt automatically carries the project's settled axes (`docs/decisions/`), the sources already read, and the last six prior runs (`swarms/*/report.md`), so tell agents to ratify or refute by reference rather than re-derive.

## Running it and watching

- Start the hub with `CHATROOM_INSECURE_LOCAL=1` (or a `CHATROOM_HUMAN_TOKEN`) or the dashboard's write actions return 403; recruit break-out rooms inherit the run prefix automatically; when a child room concludes the hub spawns one consolidator seat for the lobby, so do not nominate a drafter in briefs.
- Check the hub first: `curl -s localhost:7717/` (it is started automatically if absent, with `CHATROOM_DATA_DIR=data CHATROOM_DEFAULT_CWD="$PWD" PORT=7717 node dist/index.js`). **Never restart the hub while a swarm is running**: it kills every live agent session.
- Run the launcher in the background (`nohup ... > swarm.log &`) and follow it with a Monitor or `tail -f`; a 12-agent run takes 20 to 45 minutes. Do not block a foreground Bash on it.
- Dashboard: http://127.0.0.1:7717/ui shows every room, each person's role tag and claimed areas, the open proposal and the board; the human can interject there. Terminal: `watch-chat --latest`.
- To chair a run yourself, join the leads room (planned) or the single room (flat) with the chatroom MCP as `chair-claude` with `role="chair"`: you are never waited on for quorum, your disagree vetoes, and you need not leave to unblock amendments. Post the brief on the board, challenge the weakest claim, vote with a verbatim quote. Do not do the agents' work for them.
- Follow a room cheaply over HTTP (`/rooms/<room>/messages?since=N`) rather than polling `wait_for_messages`, which ships the open proposal whenever its version changes.
- A Claude Code seat (this one included) calls `wait_for_messages` directly and has no local re-poll loop like `--idle-waits` gives an OpenRouter seat, so it pays a full-context turn on every return, even on plain chatter. Pass `wait_for_messages(hold_until_actionable=true)` to hold the poll server-side through non-actionable chatter and only wake for something you must act on (addressed message, a vote/challenge you owe, a human message you are the nominated responder for, a conclusion) or the timeout, whichever first — no message is ever dropped. A human message addressed to someone else does not wake you: it stays invisible to bystanders (like today) until it is answered or ages out.

## Afterwards

Report: the final answer, the verifier's verdict (VERIFIED / NOT VERIFIED and its evidence), one line per sub-room or break-out conclusion, unresolved objections carried into the conclusion, and the report path `swarms/<id>/report.md` (also written if the terminal output is lost). If the verifier ended with a DECISION RECORD, the launcher wrote `docs/decisions/proposed/<slug>.md`; promote it with `guard-decisions add <slug> --target --new ...` only if the human agrees, then regenerate `docs/research-index.md` with `scripts/research-index.sh`. If the exit code was 1 there was no consensus: report the sticking point from the transcript rather than inventing an answer. If a room was closed by a human, say so.

## Usage telemetry

Every seat (`claude -p --output-format json`, the OpenRouter/Codex `<name>.usage.json` sidecar) reports its cost and tokens back to the launcher, rolled up into `result.json`'s `artifact.usage`: `steps`/`prompt_tokens`/`completion_tokens` from OpenRouter/Codex, `input_tokens`/`cache_read_input_tokens`/`cache_creation_input_tokens`/`output_tokens` from Claude seats (all optional per seat — a field a provider doesn't produce is absent, never zero), plus `cost_usd`, `seats`, `seats_with_usage` and `coverage` (`complete` | `partial` | `none`). A seat that never reports usage is *not* zero-filled into the sums; it only lowers `coverage`. `renderRunReport`'s `## Usage` line in `report.md` prints both: `N steps, N prompt + N completion tokens (claude: N input, N cache-read, N cache-creation, N output tokens), $cost across N seat(s); coverage: ...`. Treat `coverage: partial`/`none` as "some/all seats' cost is unknown", never as "the run was free".

## Integrating what a build lobby produced

Merge only branches named in the conclusion that carry a `verify/*` entry, in ranked order, onto `integration/<run>`; after every merge `npm run build && PORT=7733 npx tsx scripts/smoke.ts`; then run every branch's own regression script (`scripts/*-regression.ts`, `scripts/*.test.ts`; `NODE_OPTIONS=--experimental-vm-modules` for seat-env-regression; macOS has no `timeout`). A test that was green on its branch and is red integrated is fixed as a test, never by loosening the hub. Two runs that both touched the wait path (e.g. an attention gate and board deltas) conflict in `src/hub.ts`/`src/server.ts`: resolve as the union of both mechanisms, then re-run both runs' suites; a test from one run that encodes the other's superseded contract is rewritten to the certified contract. Fast-forward main, push, restart the hub. Record the round with `guard-decisions add ... --target --new --evidence-change`, copy the report into `docs/` with keys redacted, regenerate `docs/research-index.md`.

## Claude Code seats on Sonnet (since 2026-09-18)

OpenRouter is out of credit, so runs use Claude Code seats: `--models sonnet --verifier-model sonnet --quorum supermajority`, no `--openrouter`; seats launch lean through `src/claude-args.ts` (`--claude-full` opts out). For recruits to be Claude too, start the hub with `CHATROOM_RECRUIT_AGENT=claude` (model pin optional; `POST /policy` changes it live). **Recruiting is on by default and stays on: do not write "no recruits" into a brief or lower the hub's agent caps unless the user asks for that in so many words.** The hub's caps are read once at start and apply to every room on the hub, including rooms other sessions are running: `CHATROOM_MAX_LIVE_AGENTS` counts every live agent in every open room, not recruits, so a low value silently refuses recruiting machine-wide (on 2026-09-18 a value of 4, set for one 15-agent run and never lifted, blocked an unrelated room). Normal values: `CHATROOM_MAX_LIVE_PER_ROOM=80 CHATROOM_MAX_LIVE_AGENTS=120 CHATROOM_MAX_RECRUITS_PER_ROOM=80 CHATROOM_MAX_RECRUITS_PER_RUN=200 CHATROOM_MAX_ROOMS_PER_RUN=40 CHATROOM_MAX_RECRUIT_DEPTH=3`. Ask before changing anything on the hub that outlives the room being launched. Useful in build-room briefs: call `wait_for_messages` with `hold_until_actionable=true`; do not freeze quality baselines or add allowlist entries (a guard refuses such a commit without a `verify/baseline-*` entry by another seat; the maintainer's override is `CHATROOM_BASELINE_FREEZE_OVERRIDE=1`, which seats cannot inherit); the reviewer of a `src/hub.ts` change reads the diff. If a proposal is amended after votes were cast, check `GET /rooms/<room>` for votes marked `stale` and ask those seats to re-vote. The maintainer steers a live room with `POST /rooms/<room>/messages {name, content}`, never by editing code. A Monitor pipeline must flush every stage (`grep --line-buffered | awk '{print substr($0,1,240); fflush()}'`, never `cut`). After a hub restart, check the served dashboard script parses (`node --check` on the inline script), not just HTTP 200. Measure a run with `python3 scripts/claude-room-usage.py <run-id>` and `usage` in `swarms/<id>/result.json`. Rounds: `docs/token-round-0918.md`, `docs/review-round-0918.md`.

## Measuring a mechanic

A hub change is judged on the benchmark harness (branch merged at c36b6b9, on main): the same brief on two hub builds, hidden-fixture oracle tasks under `tasks/`, five outcomes, hashed builds per arm (`bench/results/<run>/`). Report the oracle delta, not the reply rate. First result: the day's bundled build scored -1 against the pre-gate build on one task, one seed, so mechanics are not settled by that alone. Never run `git config` from a seat: worktrees share the repository config and one seat renamed every commit author for an hour.

## Reviving a room whose seats died

Rooms outlive seats: the board, handoffs, inbox entries and worktree branches stay on the hub and on disk. `node dist/revive.js --room <name> --brief-file <file> [--names a,b] [--write --cwd-for a=<worktree>,b=<worktree>] [--verifier] [--model <slug>] [--max-minutes 60]` puts fresh seats into an existing room with a brief that starts "read every handoff/*, claim/*, inbox/* and verify/* entry, then take over"; builders get `--write` and their predecessor's worktree so they continue on the same branch; crashes (non-zero exit) are relaunched up to three times, leaves are not. Used on 2026-09-17 after OpenRouter withdrew the free model mid-run: six rooms revived with 17 seats. Revive children first and the lobby last, with the lobby told to wait for the children's conclusions.

## Requirements and gotchas

- Tests: `npm run build && PORT=7733 npx tsx scripts/smoke.ts` must print `SMOKE OK` before committing hub changes.
- `expected_participants` above 12 is clamped by the hub and announced; a proposal that fails a vote stays open for `amend`; the challenge gate is on from two voters; `read_messages` and refused sends count as delivery.
- Openings never hold a room: chat and proposals work before the reveal, and the hub reveals what it has 3 minutes after the first opening, chat or no chat (one warning first if an expected seat never joined). An agent with an outstanding @-ask is shown only that ask (plus a reply/pass hint, no board fields) on every wait or read until it replies, @-mentions back, or passes after seeing it; unrelated posts never clear it, and sends to a departed participant are refused. That is the hub, not the prompt, making a quiet seat answer; `GET /rooms/:room/stats` reports the reply rate. The board arrives as a delta of the prefixes a seat follows (`wait_for_messages(follow=[...])`), and every count (floor, blockers, conclusion line, stats) reads one `electorate()`. `npm run smoke:openrouter` (stub model, no key) covers the seat itself. A participant is swept as idle only if its MCP session is gone; connected seats may work locally for as long as the run allows.
- Recruits are pinned by the hub to one provider and model (default `openrouter` / `deepseek/deepseek-v4-flash-0731`; `stealth/union-alpha` was free until OpenRouter withdrew it mid-run on 2026-09-17 23:00 UTC, which killed every seat and its respawns in under a minute); `GET/POST /policy` or the dashboard rail changes it live; `--openrouter-models` also defaults to `deepseek/deepseek-v4-flash-0731`.
- Keep this skill in sync with `src/swarm.ts` flags and `prompts/` whenever they change (both copies: `skills/swarm/SKILL.md` in the repo and `~/.claude/skills/swarm/SKILL.md`).
